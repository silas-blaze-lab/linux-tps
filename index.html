Question : Décrivez brièvement le rôle du répertoire /home/nom_utilisateur dans Linux.

Réponse : C'est le répertoire personnel (Home Directory) de l'utilisateur. Il sert à stocker les données privées, les documents et les fichiers de configuration de cet utilisateur spécifique, garantissant la sécurité et l'isolation des données entre les différents utilisateurs du système.

Question : Quel est l'effet précis de la commande cd .. ? Expliquez son rôle dans la navigation.

Réponse : La commande cd .. permet de remonter d'un niveau dans l'arborescence des fichiers pour revenir au répertoire parent du dossier actuel. Le symbole ".." représente systématiquement le parent du répertoire courant.

[ibrahim@Ubuntu ~/TD1]$ ls

[ibrahim@Ubuntu ~/TD1]$ cat tsdi1 # Vérifier le contenu saisi
Question : Quelle est la différence entre touch et un éditeur comme nano dans la création et la gestion de fichiers ?

Réponse : La commande touch est principalement utilisée pour créer rapidement un fichier vide (ou mettre à jour ses horodatages) sans ouvrir d'interface. En revanche, nano est un éditeur de texte en ligne de commande qui permet à la fois de créer un fichier et d'ouvrir une interface interactive pour écrire, modifier et manipuler son contenu textuel.

Exercice 5 : Copie de fichiers et répertoires

Créer un dossier de sauvegarde et manipuler la commande cp avec options.

[ibrahim@Ubuntu ~/TD1]$ mkdir backup
[ibrahim@Ubuntu ~/TD1]$ cp tsdi1 backup/
[ibrahim@Ubuntu ~/TD1]$ cp -i tsdi2 backup/ # Demande de confirmation si le fichier existe déjà
[ibrahim@Ubuntu ~/TD1]$ cp -r /etc etc_Copie # Copier tout le répertoire etc
Question : À quoi sert l'option -r lors d'une copie ? Pourquoi est-elle indispensable pour les répertoires ?

Réponse : L'option -r (ou -R) signifie "récursif". Elle est indispensable pour copier des répertoires car, par défaut, la commande cp ne copie que les fichiers simples. L'option récursive force le système à copier le dossier cible ainsi que tout son contenu (sous-dossiers et fichiers inclus) en conservant la structure.

Exercice 6 & 7 : Suppression de fichiers et de répertoires

Supprimer des fichiers avec ou sans confirmation, et supprimer des répertoires vides ou pleins.

[ibrahim@Ubuntu ~/TD1]$ rm tsdi3
[ibrahim@Ubuntu ~/TD1]$ rm -i tsdi2 # Suppression avec demande de confirmation
[ibrahim@Ubuntu ~/TD1]$ rmdir dossier_vide # Supprime uniquement s'il est vide
[ibrahim@Ubuntu ~/TD1]$ rm -r backup # Supprime le répertoire et tout son contenu
Question : Pourquoi faut-il faire preuve d'une très grande prudence avec la commande rm -r ? Donnez une justification technique.

Réponse : Sur Linux, la commande rm -r supprime définitivement les données de manière récursive sans passer par une "corbeille". D'un point de vue technique, le système libère immédiatement les inodes et les blocs de données associés aux fichiers sur le disque dur. Il est donc extrêmement difficile, voire impossible sans outils de forensic poussés, de récupérer ces données en cas d'erreur (surtout si elle est exécutée avec les privilèges root via sudo).

TP 4 : Programmation Shell (Scripts)

Script 1 : Calcul de moyenne et mentions 
#!/bin/bash
sum=0; count=0
while true; do
    read -p "Saisir une note (ou 'q' pour quitter) : " input
    [[ "$input" == "q" ]] && break
    if (( $(echo "$input < 10" | bc -l) )); then echo "Ajourné"
    elif (( $(echo "$input < 12" | bc -l) )); then echo "Passable"
    else echo "Bien"; fi
    sum=$(echo "$sum + $input" | bc -l); count=$((count + 1))
done
[ $count -gt 0 ] && echo "Moyenne: $(echo "$sum/$count" | bc -l)"
Script 2 : Vérification d'existence d'utilisateur 
#!/bin/bash
read -p "Login : " user
grep -q "^$user:" /etc/passwd && echo "Existe" || echo "N'existe pas"
Script 3 : Affichage des membres d'un groupe 
#!/bin/bash
read -p "Groupe : " grp
grep "^$grp:" /etc/group | cut -d: -f4
Script 4 : Copie sécurisée avec paramètres 
#!/bin/bash
if [ $# -ne 2 ]; then echo "Usage: $0 source destination"; exit 1; fi
[ -f "$1" ] && cp "$1" "$2" && echo "Copié" || echo "Erreur"
Script 5 : Modification interactive des droits 
#!/bin/bash
read -p "Fichier : " f; read -p "Droits (ex: 755) : " d
[ -e "$f" ] && chmod "$d" "$f" && ls -l "$f"
